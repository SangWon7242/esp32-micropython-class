## 1. 학습 목표

| 구분 | 목표 |
|---|---|
| **내용 목표** | 초음파로 잰 거리를 `if` 로 판단해 서보(문)와 OLED(화면)를 함께 제어한다 |
| **사고력 목표** | 문제를 세 덩어리로 분해하고, 실행 결과를 미리 예측하고, 증상에서 원인을 역추적한다 |

### 성공 기준 (학생 언어, 칠판에 적어 두기)

1. 센서가 거리를 어떻게 재는지 **내 말로** 설명할 수 있다
2. 문이 열리는 기준 숫자를 **내가 정하고 그 이유를 말할** 수 있다
3. 오류가 났을 때 **어디부터 봐야 할지** 안다

## 4. 교사의 핵심 질문

**정답을 말하지 않고 되묻는 질문만 적었습니다.**

### 도입 (문제 이해 · 조건 분석)
- 문이 "본다"는 건 눈이 있다는 뜻일까요? 그럼 **뭘로** 보죠?
- 15cm는 누가 정했을까요? 정하는 사람이 고려할 건 뭘까요?
- "거리"를 알면 정말 충분한가요? 또 알아야 할 게 있을까요?
- 기준을 10으로 하면? 100으로 하면 어떤 일이 생기죠?

### 1부 (예측 · 실행 · 분석)
- 왜 그렇게 예측했나요? **근거를 한 문장으로** 말해 보세요.
- 손으로 센서를 완전히 덮으면 왜 0이 **안** 나올 수도 있을까요?
- 소리가 "다녀온" 시간인데 왜 2로 나누죠?
- `t = t // 2` 를 빼면 숫자가 어떻게 달라질까요?
- `print` 를 `if` 안에 넣는 것과 밖에 두는 건 뭐가 다르죠?

### 디버깅
- 이 증상이면 **어디부터** 봐야 할까요? 배선? 코드?
- 셋 중 **에러 메시지가 뜨는 건** 어느 것인가요? 왜 나머지는 안 뜨죠?

### 2부 (설계 · 완성)
- "문을 연다"를 컴퓨터가 알아듣게 쓰려면 뭐가 필요할까요?
- 1부 정답과 비교하면 **바뀐 줄은 몇 줄**인가요?
- `show()` 를 함수로 묶으니 뭐가 좋아졌나요?
- 5V와 GND는 왜 셋이 나눠 써도 괜찮을까요?

### 성찰
- 막힌 곳을 **어떻게** 알아냈나요? 무엇부터 의심했죠?
- 처음 예측과 실제 결과는 얼마나 달랐나요?
- 오늘 쓴 방법 중 **다른 수업에서도** 쓸 수 있는 게 있을까요?

## 5. 예상 오류와 지도 방법

**"마지막 수단 힌트"는 학생이 2~3번 시도한 뒤에만 줍니다.**

| 증상 | 실제 원인 | 던질 질문 | 마지막 수단 힌트 |
|---|---|---|---|
| 숫자가 계속 **0** | Trig/Echo 뒤바뀜 | "쏘는 선과 듣는 선, 어느 쪽이 13번이죠?" | 센서 몸통 글씨와 코드의 핀 번호를 나란히 읽게 한다 |
| 숫자가 **들쭉날쭉** | 3.3V에 연결 | "전원이 몇 V 로 들어가 있나요?" | 5V 핀으로 옮기게 한다 |
| 숫자가 **안 나옴** | 배선 빠짐 / 보드 미인식 | "REPL 창에 뭐라고 떠 있나요?" | GND부터 다시 꽂게 한다 |
| **멈춘 듯 반응 없음** | `while not echo.value()` 무한 대기 (센서 미연결) | "코드가 지금 뭘 기다리고 있을까요?" | Ctrl+C 로 멈추고 Echo 선 확인 |
| `IndentationError` | `if` 아래 들여쓰기 누락 | "에러가 몇 번째 줄이라고 하나요?" | 들여쓰기가 "if 안인지 밖인지"를 정한다고 설명 |
| `SyntaxError` | 콜론(`:`) 누락 | "`if` 줄 끝에 뭐가 있어야 하죠?" | 다른 `if` 줄과 비교하게 한다 |
| **10초에 한 번만** 잼 | `sleep_us(10)` → `sleep(10)` | "`_us` 가 붙고 안 붙고가 뭘 바꿀까요?" | 1초 = 1,000,000 마이크로초 |
| 화면이 **안 켜짐** | `ssd1306.py` 미업로드 | "보드 안에 어떤 파일들이 있나요?" | File System 탭에서 확인시킨다 |
| 화면 글씨가 **안 바뀜** | `oled.show()` 누락 | "적어 두는 것과 보여 주는 것은 같나요?" | `show()` 는 "화면에 내보내기" |
| `TypeError` | `str(d)` 누락 | "`d` 는 숫자일까요 글자일까요?" | 화면에는 글자만 들어간다 |
| 문이 **안 닫힘** | 열고 닫는 값이 같음 | "두 `duty_u16` 숫자를 비교해 보세요" | 1638 = 닫힘, 8100 = 열림 |
| 문이 **덜덜 떨림** | 기준 거리 경계에서 진동 | "15cm 바로 근처에 서 있으면 어떻게 될까요?" | 열림/닫힘 기준을 다르게 (추가 미션 2) |
| 서보가 **지지직** | 전원 부족 / 50Hz 미설정 | "서보에 몇 V 가 가고 있나요?" | `servo.freq(50)` 확인 |

### 안전 · 하드웨어
- ⚠️ **초음파 센서는 전원을 끈 상태에서 연결**합니다. 부득이하면 **GND를 가장 먼저** 꽂습니다.
- 배선이 끝난 조는 **짝 조의 "검사관"** 이 되어 서로 확인하게 하면 오배선이 크게 줄어듭니다.

## 6. 마무리 성찰 질문

1. 오늘 **가장 오래 막혔던 곳**은 어디였고, 어떻게 풀었나요?
2. `15` 라는 숫자를 왜 그 값으로 정했나요? `30` 이면 무엇이 달라지나요?
3. 이 자동문을 **학교 어디에** 달면 좋을까요? 그러려면 무엇을 바꿔야 하죠?

**진행 방법 (슬라이드 42)** — 공책에 먼저 쓰기 → 순회하며 2~3명에게 1분씩 설명 듣기 → 전원 공책에 한 줄 남기기.

**기록 틀**
```
막힌 곳 →  내가 해 본 것 →  결국 원인은 →  다음엔 여기부터 본다
```

## 7. AI 활용 안내 (슬라이드 43)

| ❌ 이렇게 묻지 않기 | ✅ 이렇게 묻기 |
|---|---|
| "자동문 코드 짜 줘" | "`IndentationError` 가 무슨 뜻인지 알려 줘" |
| "이거 고쳐 줘" | "내 코드가 왜 0을 내는지 **질문 3개만** 던져 줘" |
| "정답 알려 줘" | "내 설명이 맞는지 봐 줘. 나는 ~라고 생각해" |
