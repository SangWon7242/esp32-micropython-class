# KS5020 ESP32 PLUS 실기 검증 시나리오 (교사용)

> 자동화 테스트는 **가상 시리얼 기기(mock)**로 수행했습니다. 실제 하드웨어 통과를 의미하지 않습니다.
> 교사 또는 관리자 입회하에 테스트하고 안전 배선 확인 전에는 **실행을 누르지 마세요**.

## 1. 준비
- Keyestudio ESP32 PLUS (MicroPython 펌웨어 설치 완료), **데이터 전송이 가능한** USB 케이블.
- 컴퓨터의 Chrome/Edge 데스크톱, HTTPS 또는 localhost로 접속.
- Thonny, PyCharm, Arduino IDE의 해당 COM/tty 포트 연결을 종료.
- ESP32 GND → LED 음극, **GPIO26 → 220Ω → LED 양극**. 전원 분리 상태에서 구성한 뒤 다시 연결.
- 전기부품 사양과 GPIO 라벨 재확인. ESP32 GPIO에 5V 신호 직접 입력 금지.

## 2. 필수 수동 테스트 체크리스트
1. [ ] 홈 → 과정 → 챕터 → 개념 퀴즈 → 회로 연결 → 작은 미션 순으로 열고 닫힘 동작 확인.
2. [ ] 첫 번째 미션이 잠겨 있다가 직전 단계 완료 후 열리는지 확인.
3. [ ] 블록을 움직이면 MicroPython이 변경되며 텍스트 수정 시 지원 구문만 블록으로 변환되는지 확인.
4. [ ] USB 연결 클릭 → 포트 선택 → 화면의 연결 상태가 `USB 연결됨`인지 확인.
5. [ ] `led-on` 코드(GPIO26)를 실행 → LED가 켜지는지 **육안 확인**.
6. [ ] `led-off` 코드 실행 → LED가 꺼지는지 확인.
7. [ ] `led-after-1s` 코드 실행 → 약 1초 후 LED가 꺼지는지 관찰.
8. [ ] `led-forever` 코드 실행 → LED 반복 깜박임, `■ 중지 / 복구` → 중지 여부 확인.
9. [ ] `led-python` 에서 `time.sleep_ms(100)` 수정 → 화면 코드 채점 통과 및 실제 속도 확인.
10. [ ] 장치 분리 후 연결 상태가 `연결 안 됨`으로 바뀌는지 확인.
11. [ ] 포트를 다른 앱이 선점할 때 에러 문구와 복구 안내가 보이는지 확인.
12. [ ] 포트 연결 후 USB 선 뽑기 → 시리얼 오류 처리, 재연결 확인.
13. [ ] 센서값 `print()` 출력이 시리얼 모니터에 보이는지 확인.
14. [ ] 완료 후 페이지 새로고침 → 단계 진도와 관찰 메모 저장 유지 확인.

## 3. 전송 및 진단 규칙
- 펌웨어는 raw-paste REPL(`Ctrl-A` → `Ctrl-E A Ctrl-A`)를 지원해야 합니다. 미지원 시 **중단**하며 불안정한 일반 raw REPL 전송으로 자동 전환하지 않습니다.
- 업로드 응답은 기기가 코드를 **수신 및 컴파일 시작**했다는 신호입니다. 센서 동작 성공 신호가 아닙니다.
- 브라우저 시리얼 모니터와 Thonny 같은 별도의 시리얼 프로그램을 동시에 연결하지 마세요.
- 코드가 무한 반복하는 경우 중지 버튼을 이용하세요. 중지 후 GPIO 출력은 원상 복귀하지 않을 수 있습니다.
- USB 중 전원 불안정, 보드 리셋, 펌웨어 변경, 표준 raw-paste가 없는 보드는 재검증이 필요합니다.

## 4. 교안과 라이선스
- 학습 미션과 배선 안내는 자체 작성되었습니다. KS5020 공식 문서의 내용을 참고하되 저작권이 있는 그림/코드를 복사하지 않았습니다.
- 공식 원문: https://docs.keyestudio.com/projects/KS5020/en/latest/docs/2.%20MicroPython_Tutorial.html
- 공식 MicroPython REPL: https://docs.micropython.org/en/v1.27.0/reference/repl.html
- 주의: GPIO26+220Ω은 Keyestudio Hello LED 예제와 일치합니다. 다른 챕터 GPIO 배선은 교육용 예시로, 실제 모듈 및 펌웨어에 맞게 확인해야 합니다.
